# Interview Prep

Create structured interview plans to evaluate candidates consistently and fairly.

## Interview Design Principles

1. **Structured**: Same questions for all candidates in the role
2. **Competency-based**: Map questions to specific skills and behaviors
3. **Evidence-based**: Use behavioral and situational questions
4. **Diverse panel**: Multiple perspectives reduce bias
5. **Scored**: Use rubrics, not gut feelings

## Interview Plan Components

### Role Competencies
Define 4-6 key competencies for the role (e.g., technical skills, communication, leadership, problem-solving).

### Question Bank
For each competency, provide:
- 2-3 behavioral questions ("Tell me about a time...")
- 1-2 situational questions ("How would you handle...")
- Follow-up probes / "Look for" signals for interviewers
- Technical probe questions (for engineering roles)

### ✅ Recommended Answers (REQUIRED)
**For every question in the question bank, you MUST write a recommended model answer immediately below it.**

Format each answer using the following blockquote style:

```
> **✅ Recommended Answer:**
> "<Answer text here. Use concrete examples, measurable outcomes, and technical depth appropriate to the role.>"
```

Recommended answers must:
- Be written in first-person, as if a strong candidate is speaking
- Use the **STAR method** (Situation, Task, Action, Result) for behavioral questions
- Provide concrete technical detail for technical/situational questions (with code snippets where relevant)
- Cover edge cases, trade-offs, and "why" reasoning — not just "what"
- Reflect the seniority level of the target role (e.g., senior answers show leadership, architecture decisions, and prevention mindset)
- Be realistic and specific — avoid vague or generic answers

For **Technical Probe Questions**, answers must include:
- A clear conceptual explanation
- A code example or diagram where applicable
- Comparison tables for "A vs B" questions
- Real-world use case or practical scenario

### Scorecard
Rate each competency on a consistent scale (1-4) with clear descriptions of what each level looks like.

### Debrief Template
Structured format for interviewers to share findings and make a decision.

### Screening Tasks (Optional)
For technical roles, include 2-4 async screening tasks that can be sent before the live interview. For each task:
- Provide the problem statement
- Include a **✅ Reference Solution** immediately below with working code and explanation

## Output

Produce a complete interview kit containing:
1. **Panel Assignment** — who interviews for what, with round names and durations
2. **Question Bank by Competency** — behavioral, situational, and technical probe questions, each followed by a `✅ Recommended Answer`
3. **Scoring Rubric** — 1–4 scale with level descriptions
4. **Scorecard Template** — fillable grid for interviewers
5. **Debrief Template** — structured post-interview decision format
6. **Screening Tasks** (for technical roles) — with `✅ Reference Solutions`

> **CRITICAL**: Never leave a question without a recommended answer. Every `Q:` or numbered question must be immediately followed by a `> ✅ Recommended Answer:` block.
